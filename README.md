# 관심종목 실시간 뉴스 알림 봇

관심종목 11개와 산업 테마 3개(ESS·AIDC·반도체)를 5분마다 확인해서,
**새로 뜬 기사만** 골라 텔레그램으로 원문 링크와 함께 보냅니다.
GitHub Actions 위에서 돌기 때문에 내 PC를 꺼도 24시간 작동합니다.

---

## 설치 (한 번만, 약 15분)

### 1단계 · 텔레그램 봇 준비

이미 리포트를 받고 있는 봇이 있으면 **그 봇을 그대로 쓰면 됩니다.** 토큰만 있으면 돼요.
새로 만들려면:

1. 텔레그램에서 `@BotFather` 검색 → `/newbot` → 이름과 아이디를 정하면 토큰을 줍니다.
   (`8123456789:AAF...` 형태 — 이게 `TELEGRAM_BOT_TOKEN`)
2. 만든 봇과의 대화방에 들어가 아무 메시지나 하나 보냅니다. (이걸 해야 봇이 나를 인식합니다)
3. 내 대화방 번호(`TELEGRAM_CHAT_ID`)를 알아냅니다. 아래 주소를 브라우저 주소창에 넣고 `chat` 안의 `id` 숫자를 찾으면 됩니다.

   ```
   https://api.telegram.org/bot토큰을여기에/getUpdates
   ```

   찾기 어려우면 이 폴더의 `get_chat_id.py`를 쓰세요. 파이썬이 깔린 컴퓨터에서:

   ```bash
   pip install requests
   TELEGRAM_BOT_TOKEN=내토큰 python3 get_chat_id.py
   ```

### 2단계 · 네이버 검색 API 키 (무료)

> **주의** — 네이버가 2026년 7월 31일자로 검색 API를 기존 개발자센터(developers.naver.com)에서
> **NAVER API HUB(네이버 클라우드 플랫폼)** 로 옮겼습니다.
> 개발자센터의 `사용 API` 목록에 `검색`이 없는 건 이 때문이니, 아래 경로로 가세요.

1. <https://www.ncloud.com/> 에서 회원가입 (휴대폰 본인인증 + 결제수단 등록이 필요합니다.
   무료 한도 안에서는 청구되지 않습니다)
2. 콘솔 접속 → 상단 **Menu → All Services → Application Services → NAVER API HUB**
3. **신청하기** 클릭 → 사용할 API에서 **검색(Search)** 선택
4. **Application 등록** → 이름은 아무거나 (예: `종목알림`)
5. 등록된 Application의 **인증 정보**에서 **Client ID**와 **Client Secret** 확인

> 무료 한도는 검색 API 통합 **월 775,000건**입니다. 이 봇은 월 12만 건쯤 씁니다.
> 초당 요청은 50건 제한인데, 이 봇은 호출 사이에 간격을 두고 있어 걸릴 일이 없습니다.

**예전에 개발자센터에서 이미 발급받은 키가 있다면 그것도 그대로 씁니다.**
스크립트가 첫 호출에서 새 주소와 옛 주소를 모두 시도해 되는 쪽을 자동으로 잡습니다.

### 3단계 · GitHub 저장소 만들기

1. <https://github.com/new> 에서 새 저장소 생성
2. 이름은 아무거나 (예: `stock-alert`), **Public**으로 만드세요
   → Public이면 Actions 실행 시간이 **무제한 무료**입니다. Private은 월 2,000분 제한이라 5분 간격이면 금방 소진됩니다.
   → 코드가 공개돼도 **API 키는 저장소에 안 들어갑니다.** 아래 4단계의 Secrets에 따로 넣습니다.
3. 이 폴더의 파일을 전부 저장소에 올립니다. (`Add file` → `Upload files`로 드래그하면 됩니다.
   단, `.github/workflows/alert.yml`은 폴더 구조가 유지돼야 하니 **압축을 푼 폴더째로 드래그**하세요)

### 4단계 · 열쇠 4개 등록

저장소에서 **Settings → Secrets and variables → Actions → New repository secret**을 눌러
아래 4개를 하나씩 넣습니다. 이름 철자를 정확히 맞춰야 합니다.

| 이름 | 값 |
|---|---|
| `TELEGRAM_BOT_TOKEN` | 1단계의 봇 토큰 |
| `TELEGRAM_CHAT_ID` | 1단계의 chat id 숫자 |
| `NAVER_CLIENT_ID` | 2단계의 Client ID |
| `NAVER_CLIENT_SECRET` | 2단계의 Client Secret |

### 5단계 · 켜기

1. 저장소 **Actions** 탭 → 초록 버튼(`I understand my workflows, go ahead and enable them`) 클릭
2. 왼쪽에서 `관심종목 실시간 알림` 선택 → 오른쪽 **Run workflow** 클릭
3. 첫 실행은 **"시작했습니다" 메시지 하나만** 옵니다.
   과거 기사가 한꺼번에 쏟아지지 않도록 기존 기사를 전부 읽음 처리하기 때문입니다.
   그 다음부터 새로 뜨는 것만 옵니다.
4. 이후로는 5분마다 자동으로 돕니다. 아무것도 안 해도 됩니다.

> **켜기 전에 점검부터 하고 싶다면** Run workflow에서 `check`를 체크하세요.
> 네이버 키가 붙는지 확인하고 텔레그램으로 테스트 메시지를 한 통 보냅니다.
> 로그에 어느 주소로 연결됐는지, 실패면 상태코드가 뭔지까지 찍히니 문제 파악이 쉽습니다.
>
> `dry_run`은 실제 폴링을 돌리되 텔레그램으로 안 보내고 로그에만 남기는 옵션입니다.

## 알림은 이렇게 옵니다

```
🔔 후성 · 종목
후성, WF6 증설 투자 결정… 반도체 특수가스 공급 확대
설명 첫 문장이 여기 붙습니다
🔗 기사 원문 · 09/08 14:32 · 네이버
```

```
🏭 ESS · 산업
미국 ESS 프로젝트 대규모 발주… 국내 배터리사 수혜
🔗 기사 원문 · 09/08 11:05 · 네이버
```

`기사 원문`은 언론사 원문 URL, `네이버`는 네이버 뉴스 링크입니다. 눌러서 바로 읽으면 됩니다.

## 종목을 바꾸고 싶을 때

`config.json`만 고치면 됩니다. GitHub에서 파일을 눌러 연필 아이콘으로 바로 편집해도 되고,
고치고 저장하면 다음 실행부터 반영됩니다.

```json
{
  "name": "한중엔시에스",
  "code": "107640",
  "queries": ["한중엔시에스", "한중엔시에스 ESS"],
  "must_include_any": ["한중엔시에스"],
  "exclude_any": []
}
```

- `name` 알림에 표시될 이름
- `code` 6자리 종목코드 — 지금은 쓰지 않고 메모용입니다. 비워도 동작합니다
- `queries` 네이버에 검색할 말들. 여러 개 넣으면 더 넓게 훑습니다
- `must_include_any` 이 중 하나라도 제목·요약에 없으면 버립니다 (엉뚱한 기사 차단)
- `exclude_any` 이 중 하나라도 있으면 버립니다

> **이름이 흔한 단어인 종목은 `exclude_any`가 중요합니다.**
> 예를 들어 `후성`은 "후성유전학"을 걸러야 하고, `혜인`은 사람 이름 기사를 걸러야 합니다.
> 이미 두 종목은 처리해 뒀습니다. 엉뚱한 알림이 오면 그 단어를 `exclude_any`에 추가하세요.

### 알림 양 조절

`config.json`의 `poll` 부분입니다.

| 항목 | 지금 값 | 뜻 |
|---|---|---|
| `news_lookback_minutes` | 90 | 90분보다 오래된 기사는 무시 |
| `quiet_hours_kst` | `[1,2,3,4,5]` | 새벽 1~5시에는 알림을 보내지 않음 |
| `max_news_per_cycle` | 12 | 한 번에 종목 뉴스 최대 12건 |
| `max_theme_news_per_cycle` | 4 | 한 번에 산업 뉴스 최대 4건 |

산업 테마 알림이 시끄러우면 `max_theme_news_per_cycle`을 `2`로 줄이거나,
`themes`의 `require_any`에서 넓은 단어(`전망`, `확대`)를 빼면 확 조용해집니다.
아예 안 받고 싶으면 `themes`를 `[]`로 비우면 됩니다.

## 알아둘 점

- **완벽한 초 단위 실시간은 아닙니다.** GitHub Actions의 5분 스케줄은 서버가 붐비면
  10~15분씩 밀리기도 합니다. 평균 5~10분 지연이라고 보시면 됩니다.
  더 빠르게 하려면 항상 켜둔 PC나 서버에서 `while true; do python3 alert_bot.py; sleep 60; done`으로
  돌리는 편이 낫습니다. 파일은 그대로 쓸 수 있습니다.
- **네이버 뉴스 색인에 안 잡히는 매체는 놓칩니다.** 텔레그램 채널이나 증권사 리포트는 대상이 아닙니다.
- **기사가 나기 전에 움직이는 재료는 못 잡습니다.** 공시나 체결 데이터가 뉴스보다 먼저인 경우가 많은데,
  이 봇은 기사만 봅니다. 나중에 필요해지면 공시 감시를 붙일 수 있습니다.
- 읽음 기록은 GitHub Actions 캐시에 저장됩니다. 7일 넘게 실행이 없으면 캐시가 사라지고,
  그때는 다시 "첫 실행"처럼 조용히 읽음 처리부터 시작합니다.

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 아무 알림도 안 옴 | Actions 탭에서 실행이 초록색인지, 로그에 `새로 잡힌 기사 0건`인지 확인 |
| `텔레그램 전송 실패 400` | `TELEGRAM_CHAT_ID`가 틀렸거나, 봇에게 먼저 말을 안 걸었음 |
| `네이버 API 연결 실패 (401)` | 키 오타이거나, API HUB에서 검색 API 이용신청이 안 된 상태 |
| `네이버 API 오류 429` | 호출 한도 초과. 검색어(`queries`) 개수를 줄이세요 |
| 네이버 쪽이 계속 안 붙음 | Run workflow에서 `check`를 켜고 로그의 상태코드를 확인하세요 |
| 엉뚱한 기사가 옴 | 해당 종목의 `exclude_any`에 그 단어 추가 |
| 같은 기사가 두 번 옴 | 언론사가 URL을 바꿔 재송고한 경우. 드물게 있습니다 |

수동 실행 시 `reset`을 체크하면 읽음 기록을 지우고 처음부터 다시 시작합니다.
